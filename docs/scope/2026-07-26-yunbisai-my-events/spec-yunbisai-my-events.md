# 云比赛“我的比赛”

## 目标

将现有云比赛页中跳转到官方站点的“我的比赛”入口，替换为 JCGO 内原生的报名比赛列表。用户首次通过微信扫码把云比赛账号授权给本机 JCGO，之后可在同一个云比赛页面内切换查看杭州公开比赛和自己的有效报名，并在 JCGO 内查看报名及赛事详情。

## 决策

- 云比赛页面顶层使用“杭州比赛”和“我的比赛”两个 Tab，默认保持在“杭州比赛”。
- “杭州比赛”保留现有杭州地域限制和月份筛选。
- “我的比赛”不提供月份、地域或状态筛选，内部可分页加载，但用户看到的是一个连续列表。
- 首次进入“我的比赛”时使用云比赛官方微信二维码授权，不接收或保存用户手机号、密码。
- 授权状态由 JCGO 后端管理并持久化到本机状态目录；浏览器前端不保存、不展示云比赛令牌。
- “我的比赛”只展示赛事类订单中的待付款和已付款订单；关闭、退款、售后及非赛事订单不展示。
- 赛事类订单包括云比赛定义的赛事报名、改签、AI 赛事和综合报名。
- 点击列表项后，在“我的比赛”Tab 内显示原生详情，不新增应用级页面。
- 原生详情展示云比赛接口可提供的赛事名称、时间、地点、报名人、组别、订单状态和订单信息，并提供“打开云比赛原始详情”。
- 支付、退款、改签及其他订单操作继续由云比赛官方页面处理。

## 架构

JCGO 后端新增云比赛账号会话与订单适配层，负责执行官方扫码登录流程、持有远端 Cookie/令牌、请求订单及详情接口，并向前端返回最小化的领域数据。会话凭证只保存在本机 JCGO 状态目录，不写入前端存储、URL 或日志。前端仅调用 JCGO 同源接口，负责二维码、账号选择、登录状态、列表和详情的展示。

云比赛是外部且未版本化的依赖。适配层必须严格校验响应结构，把未登录、授权过期、远端格式变化和网络错误区分为稳定的本地错误；任何远端异常不得影响现有杭州公开比赛列表。

## 流程

1. 用户进入云比赛页，默认看到“杭州比赛”；切换到“我的比赛”。
2. 未授权时，JCGO 后端向云比赛申请二维码，前端显示二维码并轮询登录状态。
3. 用户使用微信扫码。若云比赛返回多个账号，前端显示账号列表供用户选择；单账号可直接确认。
4. JCGO 后端完成账号选择，保存会话凭证，然后请求订单列表。
5. 后端仅保留赛事类且状态为待付款或已付款的订单，转换为 JCGO 订单模型后返回。
6. 用户点击订单，后端按订单号获取详情并转换为赛事详情模型；前端在当前 Tab 内展示并支持返回列表。
7. 会话过期时，后端清除无效凭证，前端回到扫码状态并明确提示需要重新授权。
8. 用户可主动切换账号或退出；两种操作都会清除当前 JCGO 云比赛会话，再进入扫码流程。

## 验收标准

- 云比赛页有“杭州比赛”和“我的比赛”两个顶层 Tab，默认 Tab 和现有杭州比赛行为不变。
- 月份筛选只出现在“杭州比赛”，不会影响“我的比赛”。
- 未授权用户进入“我的比赛”后能看到可扫描的微信二维码，以及等待、过期、失败和重试状态。
- 多账号扫码时必须由用户选择账号；单账号流程可以直接完成。
- 授权成功后，刷新浏览器或重启 JCGO 仍能恢复有效会话。
- 前端资源、URL 和普通日志中不出现云比赛令牌、Cookie 或登录密钥。
- 列表只出现待付款或已付款的赛事类订单，不出现已关闭、退款、售后或非赛事订单。
- 列表至少展示赛事/订单名称、状态和创建时间；无订单时显示明确空状态。
- 点击订单能在当前“我的比赛”Tab 内看到可获得的赛事时间、地点、报名人、组别和订单信息，并能返回列表。
- 详情提供“打开云比赛原始详情”；待付款订单可通过官方页面继续付款。
- 云比赛返回未登录时回到授权状态；网络错误和数据格式错误提供重试，不误报为空列表。
- 杭州公开比赛接口和展示不因“我的比赛”接口失败而受影响。

- 后端测试确认敏感凭证不进入 API 响应和日志。
- 前端组件测试覆盖 Tab 切换、月份筛选隔离、扫码状态、多账号选择、列表空态与错误态、订单过滤结果展示、详情与返回、退出和切换账号。
- 保留现有云比赛公开列表回归测试，并运行全部 Go 测试、前端测试和生产构建。
- 不在自动化测试中进行真实微信扫码、真实支付、退款或改签。

## 范围之外

- 在 JCGO 内实现支付、退款、售后或改签。
- 保存云比赛手机号、密码或绕过官方扫码授权。
- 修改云比赛账号、报名资料或订单。
- 为“我的比赛”增加月份、城市、状态搜索或筛选。
- 将云比赛会话同步到其他设备或其他浏览器。
